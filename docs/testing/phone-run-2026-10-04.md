# Phone run, 4 Oct 2026: fixes

Run on Raj's iPhone (iOS 27, Release build). One line per finding.

1. Restoring a backup from the first screen lost the monthly budget. Setup noted the budget when it opened (none) and put that back at the end. The Import sheet and the iCloud restore now adopt the restored budget as the starting point (`SetupBudgetMemory`). Tests: `RestoreBudgetThroughSetupTests` (`restoreFromTheFirstScreenKeepsTheBudgetThroughSetup`).
2. `.sortdbackup` was not a declared file type ("Keep Both" gave `... .sortdbackup 2`). Exported type `com.kameshraj.spend.backup` added to `Spend-Info.plist`; one constant `Backup.fileType` replaces the dynamic lookups. No "Open in" handler added. Tests: `BackupFileTypeTests`.
3. Removed the "Updated 2 Oct: get it again..." line, its `AppStorage` flag and its test. Test removed with it: `theUpdateLineShowsOnlyForAnOldConnectedShortcut`.
4. The Import sheet from the first screen had no way out. Added a Cancel (xmark) toolbar button, the same as the other sheets. No logic test (view only).
5. Sign-in copy said the iCloud copy is tied to you. iCloud backup does not use the account, so the row now reads "Delete it any time: Delete your account in Settings and your usage record goes with it." No logic test (copy only).
6. Export as Spreadsheet showed nothing for a few seconds. It is now a button that shows a spinner and is disabled while the file is made, then opens the share sheet. Save a Backup already did this. No logic test (view only).
7. A popover tip showed on the wrong tab. `SortdPopoverTip` now gives the tip to TipKit (and counts it as shown) only while its view is on screen. Also, purchases dated more than 400 days back no longer count towards "days of data" or "months of data". Tests: `TipStateTests` (`aPurchaseDatedYearsAgoDoesNotCountAsDaysOfData`, `aYearOfImportedHistoryStillCounts`, `onlyJunkDatesMeansNoData`). The on-screen gate is view code: not run on a device.
8. Get the Shortcut sometimes showed a page stuck loading or a blank page (iCloud link sent to the default browser). Dropped the iCloud link. The button now opens our signed file `https://sortd.page/apple-pay.shortcut` in an in-app Safari sheet (`SafariSheet`), never `openURL` or the default browser. On the iOS 27 simulator the sheet shows a file card with "Open in Shortcuts" (no Download step), so the footnote says "A page opens. Tap Open in Shortcuts." Support page and the build script note point back to the hosted file. Tests: `ApplePayOnlineSetupTests` (`getTheShortcutOpensTheHostedFileInTheSafariSheet`). `site/_headers` left as `application/octet-stream`: no Apple-documented type could be checked.
9. Replaced by item 8 (no iCloud link, so no "get the file instead" route).
10. The small Spending widget said "of $65 a day" while Home said "$70 a day" (budget over all 31 days vs what is left over the days left). Both now use `WidgetSummary.perDay`; the widget's `dayAllowance` is that figure. Tests: `WidgetDailyFigureTests` (`homeAndTheWidgetAgreeOnTheDailyFigure`, $2,000 budget, $34.30 spent, 4 Oct).
11. The Apple Pay tip came loose and sat over the "Add a Purchase" row on the empty Home. It is now an inline card (`SortdTipView(tip: ApplePayTip())`) under the Finish Setup list, shown only while the Apple Pay row is not done; same `TipRules.applePay` eligibility and `tip_shown` reporting. Checked on the iOS 27 simulator, light and dark: nothing overlaps. At the largest text size the card sits below the fold in a scroll view. No logic test (view only).
12. The Amount number pad on a purchase's detail screen had no way to close. Added a keyboard "Done" button (same as New Purchase) and `.scrollDismissesKeyboard(.interactively)`. No logic test (view only); not tapped in the simulator.
13. "Show me how" and "Build it by hand instead" shared no state in code, but one tap opened both on iOS 26.4. Each now has its own explicit expanded state. Not reproduced: only an iOS 27 simulator is available, and I could not tap in it.
