took off (tap-vs-tap keeps 10 minutes). A bank's refund needs a refund verb tied to the money
("Refund of", "refunded", "refund to your…"); a spend word before the amount and a refund verb
together save nothing. Equal amounts are counted before they are taken out. Every incoming
field is cut to 1,000 characters, and the "6.20 SGD" pattern starts only where a number starts.

### Rejected

D1 "Restoring the old iPhone's backup makes the new iPhone's Apple Pay step read as set up": NOT A BUG against the written spec. The code does it, and the test fails as the finder said. But `docs/specs/2026-09-25-apple-pay-page.md:69` says a restored tap row means `.tapLogged`, and `ApplePayStatusTests.swift:50-56` pins it. The verifier's note: the spec line is from 25 Sep, before setup began gating Continue on `isReady` (5 Oct), so a new iPhone now shows the step done with no shortcut on it. That needs a decision (for example, drop `.tap` from restored rows, or count only taps newer than this install), not a code fix. It stays in the first table for that reason.
